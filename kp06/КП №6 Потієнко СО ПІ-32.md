1. МЕТА РОБОТИ

Метою даної роботи є набуття навичок використання Django форм для створення, редагування та видалення записів у таблиці атмосферних вимірювань, а також виконання тестування розробленого функціоналу.

2. ЗАВДАННЯ

- Взяти за основу веб-додаток таблиці атмосферних вимірювань з попереднього практикуму.
- Додати до веб-додатку можливості створювати нові записи, їх редагування та видалення.
- Виконати тестування створеного додатку.
- Зберегти зміни до git-репозиторію.
- Оформити протокол виконаної роботи.
- Запакувати до архіву файли, додані до репозиторію.

3. ХІД ВИКОНАННЯ

У результаті виконання практичної роботи було створено Django-проєкт kp06 (proj_ste_pot) з наступною структурою файлів:

- manage.py – утиліта для управління проєктом
- db.sqlite3 – файл бази даних
- posts/__init__.py – файл, що позначає директорію як пакет Python
- posts/models.py – моделі Measurement та Post
- posts/views.py – універсальні представлення (ListView, DetailView, CreateView, UpdateView, DeleteView)
- posts/urls.py – маршрутизація URL для сторінок
- posts/admin.py – реєстрація моделей в адмінці
- posts/tests.py – тести для перевірки функціональності
- posts/migrations/ – міграції бази даних
- proj_ste_pot/__init__.py – файл, що позначає директорію як пакет Python
- proj_ste_pot/settings.py – конфігурація проєкту
- proj_ste_pot/urls.py – головна маршрутизація URL
- proj_ste_pot/wsgi.py – конфігурація для WSGI веб-серверів
- static/css/base.css – статичний файл стилів
- templates/base.html – базовий шаблон
- templates/home.html – шаблон домашньої сторінки блогу
- templates/post_detail.html – шаблон детальної сторінки допису
- templates/weather_list.html – шаблон списку вимірювань
- templates/measurement_detail.html – шаблон детальної сторінки вимірювання
- templates/measurement_new.html – шаблон створення нового вимірювання
- templates/measurement_edit.html – шаблон редагування вимірювання
- templates/measurement_delete.html – шаблон видалення вимірювання

Реалізовано наступні зміни:

1. До файлу posts/views.py додано три універсальних представлення на основі класів:
   - MeasurementCreateView (CreateView) – для створення нового запису;
   - MeasurementUpdateView (UpdateView) – для редагування існуючого запису;
   - MeasurementDeleteView (DeleteView) – для видалення запису.
   Для MeasurementDeleteView використано success_url з reverse_lazy для перенаправлення на список вимірювань після видалення.

2. У файлі posts/urls.py додано нові маршрути:
   - weather/new/ – створення запису (measurement_new);
   - weather/<int:pk>/edit/ – редагування запису (measurement_edit);
   - weather/<int:pk>/delete/ – видалення запису (measurement_delete).

3. Створено шаблони для роботи з формами:
   - measurement_new.html – відображає форму створення запису;
   - measurement_edit.html – відображає форму редагування запису;
   - measurement_delete.html – відображає сторінку підтвердження видалення.
   Усі форми використовують csrf_token для захисту від міжсайтової підробки запитів та метод POST для відправки даних.

4. Оновлено базовий шаблон base.html та шаблони weather_list.html і measurement_detail.html з посиланнями на створення, редагування та видалення записів.

5. У файлі posts/tests.py додано три тести:
   - test_measurement_createview – перевіряє створення нового запису та перенаправлення з кодом 302;
   - test_measurement_updateview – перевіряє оновлення існуючого запису;
   - test_measurement_deleteview – перевіряє видалення запису та перенаправлення з кодом 302.

Запущено тестування командою python manage.py test. Усі 7 тестів пройшли успішно:

- test_blog_listview
- test_blog_detailview
- test_weather_listview
- test_weather_detailview
- test_measurement_createview
- test_measurement_updateview
- test_measurement_deleteview

4. ВИСНОВКИ

У ході виконання практичної роботи було реалізовано повний цикл CRUD-операцій (створення, читання, оновлення, видалення) для моделі атмосферних вимірювань у Django-просторі. Використано вбудовані універсальні представлення CreateView, UpdateView та DeleteView, що значно спростило розробку. Усі зміни збережено до git-репозиторію на гілці kp06. Тестування підтвердило коректність роботи додатку.
